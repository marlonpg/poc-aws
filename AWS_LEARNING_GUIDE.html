1. AWS Basics - What You Need to Know

What is AWS?

Amazon Web Services (AWS) is a cloud computing platform that provides on-demand resources for running applications. Instead of buying physical servers, you "rent" computing power, storage, and databases that scale with your needs.

Core Concepts

  • Regions & Availability Zones: AWS has data centers in different geographic regions. Pick a region close to your users for lower latency.
  • Services: AWS offers 200+ services. We'll focus on the main ones for Java deployment:
    • EC2 - Virtual computers (servers)
    • RDS - Managed databases
    • S3 - File storage
    • ECS/Fargate - Container orchestration (Docker)
    • Lambda - Serverless functions
    • Elastic Beanstalk - Platform for deploying web apps
  • IAM: Identity and Access Management - controls who can do what in your AWS account.

Common AWS Terms

Term Meaning
Instance A virtual server (EC2)
AMI Amazon Machine Image - a template for creating instances
Security Group Firewall rules for your instance
Availability Zone A specific data center location within a region
IAM Role Permissions that allow services to interact with each other

2. Understanding the AWS Free Tier

AWS provides a free tier for 12 months. Here's what you get for Java deployments:

Service Free Tier Allowance Notes
EC2 750 hours/month (1 t3.micro instance) Shared CPU, ~1GB RAM - good for learning
RDS 750 hours/month (1 db.t3.micro) Managed database - MySQL, PostgreSQL, MariaDB
S3 5GB storage + 20K GET requests Perfect for static files and backups
Data Transfer 1GB/month outbound, free inbound Transferring data out costs money
⚠️ Important: The free tier has limits. Going over these limits will cost money. Always set up billing alerts: AWS Console → Billing → Budgets → Create Budget.

3. Deployment Options for Java Applications

Option 1: EC2 (Elastic Compute Cloud) - Full Control

What it is:

A virtual server where you have complete control. You install Java, your app, and manage everything.

✓ Full control over the environment
✓ Cheapest option on free tier (t3.micro is free)
✓ Best for learning AWS fundamentals
✗ You manage updates, security patches, monitoring
✗ Manual scaling - won't auto-expand if traffic spikes

Best for: Learning, development, simple web apps

Option 2: Elastic Beanstalk - Managed Platform

What it is:

AWS manages the infrastructure for you. You upload your code, Beanstalk handles servers, load balancing, and scaling.

✓ Simplified deployment
✓ Auto-scaling built-in
✓ Monitoring and logs included
✗ Less control than EC2
✗ Can cost more at scale

Best for: Production web applications, teams

Option 3: ECS with Fargate - Container Orchestration

What it is:

Run your Java app in Docker containers on AWS-managed infrastructure (Fargate is serverless - you don't manage servers).

✓ Modern deployment method
✓ Consistent environment (dev → prod)
✓ Auto-scaling
✗ Requires Docker knowledge
✗ More complex setup

Best for: Microservices, containerized apps, teams using DevOps

Option 4: Lambda - Serverless

What it is:

Upload your code, Lambda runs it only when triggered (HTTP requests, scheduled events, etc). You don't manage servers at all.

✓ Zero server management
✓ Pay only for execution time
✓ Auto-scales instantly
✗ ~100MB code limit
✗ 15-minute timeout per request
✗ Requires architectural changes

Best for: APIs, scheduled jobs, event-driven apps

Recommendation for Beginners

Start with EC2. It's the closest to traditional server hosting, and you'll learn how AWS works. Once you're comfortable, explore the others.

4. Quickstart: Deploy a Java App on EC2

Prerequisites

  • AWS free tier account (✓ you have this)
  • AWS CLI installed on your computer
  • A Java application (we'll create a simple one if you don't have one)
  • A terminal/command prompt

Step 1: Install AWS CLI

1 Download and install AWS CLI v2
Visit: https://aws.amazon.com/cli/
Run the installer and follow the prompts.
2 Configure AWS CLI with your credentials
In your terminal, run: 
aws configure
AWS will ask for:
  • Access Key ID
  • Secret Access Key
  • Default region (pick closest to you: us-east-1, us-west-2, eu-west-1, etc.)
  • Output format (leave as default or choose "json")

Getting credentials: AWS Console → Your Account (top right) → Security Credentials → Access Keys → Create New Access Key

Step 2: Create an EC2 Instance

3 Go to AWS Console and launch an EC2 instance
  1. Open https://console.aws.amazon.com/ec2/
  2. Click "Launch Instances"
  3. Select Amazon Linux 2 or Ubuntu (free tier eligible)
  4. Choose t3.micro instance type (free tier)
  5. Configure security group: Allow HTTP (port 80) and SSH (port 22) from anywhere (0.0.0.0/0)
  6. Create/download a key pair (save the .pem file securely) - you'll use this to SSH into your server
  7. Click "Launch"
4 Connect to your instance via SSH 
ssh -i /path/to/your-key.pem ec2-user@your-instance-public-ip
Replace the paths with your actual key file and instance IP (find IP in EC2 Console).

Step 3: Install Java and Deploy Your App

5 Once SSH'd into your instance, install Java 
sudo yum update -y
sudo yum install java-17-amazon-corretto -y
java -version
6 Upload your Java application

From your local machine (not SSH'd):

scp -i /path/to/your-key.pem /path/to/your-app.jar ec2-user@your-instance-public-ip:/home/ec2-user/
7 Run your Java application (SSH'd into instance) 
java -jar your-app.jar

If your app uses a web server, it typically listens on port 8080. You can access it at: http://your-instance-public-ip:8080

To make it production-ready:
  • Run the app in the background: nohup java -jar your-app.jar > app.log 2>&1 &
  • Use a process manager like systemd to auto-restart on failure
  • Set up a load balancer if you need high availability
  • Use HTTPS (SSL certificate) for security

5. Next Steps & Learning Path

Immediate Next Steps

  1. Create an EC2 instance and SSH into it (Step 2-4 above)
  2. Install Java and run a simple test (Step 5)
  3. Deploy a "Hello World" Spring Boot or simple servlet app
  4. Access it from your browser

Then Learn These Topics

  • Databases: Set up RDS (managed database) to connect your Java app to PostgreSQL/MySQL
  • Storage: Use S3 for file uploads and backups
  • Networking: Configure VPCs (Virtual Private Cloud) and security groups properly
  • Auto-Scaling: Set up load balancers and auto-scaling groups for production
  • Monitoring: Use CloudWatch to monitor your app's health and logs
  • Infrastructure as Code: Use Terraform or CloudFormation to automate deployment

Learning Resources

  • AWS Documentation: https://docs.aws.amazon.com (official, comprehensive)
  • AWS Free Training: https://aws.amazon.com/free/training (videos, labs, courses)
  • EC2 User Guide: https://docs.aws.amazon.com/ec2/ (detailed reference)
  • Spring Boot on AWS: Search "Spring Boot EC2 deployment tutorial" for framework-specific guides

Common Pitfalls to Avoid

  • Leaving SSH port 22 open to all IPs (restrict to your IP for security)
  • Forgetting to stop/terminate instances when not using them (can incur costs)
  • Not setting up CloudWatch alarms for billing alerts
  • Storing secrets (API keys, passwords) in your code or git - use AWS Secrets Manager
  • Running out of disk space on your EC2 instance

Pro Tips

  • Use AWS Calculator (https://calculator.aws/) to estimate costs before building
  • Enable Cost Explorer in AWS Console to see what you're spending
  • Keep your free tier resources (t3.micro, single instance) to avoid charges
  • Use AWS CLI aliases to speed up common commands
  • Join AWS communities (Reddit: r/aws, AWS forums) for help and advice
